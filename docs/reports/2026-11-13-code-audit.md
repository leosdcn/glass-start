# Glass Start 代码审计

**审计基准**为 2026-11-13 的 `main`，版本 `5.5.5`，提交 `bbcdf8a4a22dd89184aff39d20d8b1e401c5425a`。覆盖网页版与 Chrome MV3 扩展。生产源码、配置和现有测试未改动。

## P2

### 1. 双标签页清理离线缓存后，第二次刷新可能进入 503

在 Chrome 打开两个受 Worker A 控制的标签页，将测试服务切到构建 B。在其中一页点击设置中的「刷新离线缓存」，保持另一页打开。操作后的首次刷新显示 B，注册仍保有活跃的 A 和等待中的 B。再次普通刷新，A 尝试修复已删除的核心缓存。服务器只提供 B 的文档，A 因指纹不符返回 503 修复页。实测点击修复按钮可激活 B 并恢复页面。

清理先删除该 scope 的核心池，注销后仍有旧客户端。新页面重新注册时旧控制器可能继续服务。建议在可接管的 Worker 就绪前保留活跃版本核心资源，由接管流程回收。现有清理回归可扩展到双标签页和部署切换。 [设置清理](../../src/js/modules/settings.js#L665) · [页面注册](../../src/js/core/service-worker-updates.js#L133) · [核心资源修复](../../sw.js#L310) · [现有回归](../../test/data-settings-save.test.mjs#L543)

### 2. 快捷书签较多时，移动端首屏无法滚到搜索框和末尾书签

在 Chrome 模拟 `390 × 844` 并开启触屏，通过设置的文件输入导入 48 个有效书签并保存。持久化和 DOM 均有 48 条，搜索框的纵向范围是 `-97` 到 `-49` CSS 像素，末尾 8 条完全在视口外。手指上滑进入分类导航，首屏和文档的滚动位置都保持为 0。普通 8 条默认书签在 `740 × 320` 横屏模拟下也会把时钟完全挤出视口。

首屏使用固定视口高和垂直居中，快捷书签网格随行数扩张，根节点隐藏溢出，首屏手势直接切换到下一屏。建议保证首屏内容在溢出时能纵向滚动，并让切屏手势等待内容滚到边界。回归应通过设置导入多行书签，再检查短视口中的搜索框和首尾书签是否可达。 [首屏与网格](../../src/index.html#L180) · [网格](../../src/index.html#L284) · [全局溢出](../../src/styles/page.css#L59) · [屏幕高度](../../src/styles/page.css#L147) · [首屏手势](../../src/js/core/screen-input.js#L183) · [W3C Reflow 指南](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 3. 一次壁纸预览失败会持续阻断其他设置保存

在 Chrome 修改书签名，提交返回 404 的图片直链，等待外观页显示错误。连续点击两次「完成」，书签都未落盘，设置仍打开。重新选择一张可用的预设后，书签才保存。已有自定义壁纸的用户缺少在保留原壁纸的同时放弃失败选图、继续保存其他修改的入口。

失败任务仍是当前壁纸任务。每次保存都会读到同一个失败结果，在校验书签和提交任何设置前返回。建议提供放弃失败选图的操作，恢复上一次成功预览或已保存壁纸。远程图片预览还只等待加载或解码回调，代码没有应用层超时。 [设置保存](../../src/js/modules/settings.js#L504) · [等待当前任务](../../src/js/modules/wallpaper.js#L326) · [加载与失败路径](../../src/js/modules/wallpaper.js#L365)

### 4. 最新直链校验失败后，较早的请求仍可覆盖并保存壁纸

在 Chrome 提交一个响应被延迟的可用直链，随后再次打开直链输入并提交无效文本。界面提示地址无效。释放第一个请求后点击「完成」，IndexedDB 实际保存了较早提交的图片。

新直链在校验失败时直接返回，旧任务仍是当前任务，完成后会更新壁纸草稿。文件 MIME 校验也存在同类早退路径，浏览器复现使用直链。建议新提交时先作废仍在处理的旧选择，同时保留已经成功的草稿。 [直链校验](../../src/js/modules/settings.js#L288) · [迟到的草稿发布](../../src/js/modules/wallpaper.js#L384) · [文件校验](../../src/js/modules/wallpaper.js#L510)

### 5. 本地联想保留旧高亮，回车却执行网页搜索

在生产网页构建中输入 `githu`，按 ↓ 选中 GitHub，再输入 `b`。复用的 GitHub 节点仍高亮且 `aria-selected="true"`，输入框已清除 `aria-activedescendant`。按 Ctrl+Enter 实际在新标签页执行 Bing 搜索 `github`。

渲染先清空选中索引，随后复用本地候选节点，最后丢弃旧选中节点的引用。建议在复用之前清除旧节点的样式和选中属性，再按现有策略恢复选中项。回归应同时断言高亮、ARIA 和实际打开的地址。 [选中索引](../../src/js/modules/search.js#L425) · [本地节点复用](../../src/js/modules/search.js#L443) · [更新焦点引用](../../src/js/modules/search.js#L484) · [回车行为](../../src/js/modules/search-events.js#L149)

### 6. 粘贴长查询可阻塞首屏输入

在生产网页中用正常的存储记录加载一条 4,024 字符的有效书签 URL。用 Chrome 的原生输入粘贴 4,001 字符的近似查询，从 `beforeinput` 到应用输入处理返回约 **463 ms**。对相同算法的 Node 单条候选复现中，约 8,000 字符耗时约 **1.65 s**，最终保留的矩阵约 **256 MB**。

本地匹配在网络防抖前同步执行。长词的近似比较最多试三个前缀，每次填充完整编辑距离矩阵，缓冲区只扩不缩。建议限制参与模糊匹配的词长度，保留原查询用于精确匹配和提交，或用现有最大允许距离约束矩阵计算范围。 [输入事件](../../src/js/modules/search-events.js#L64) · [同步本地匹配](../../src/js/modules/search.js#L569) · [矩阵分配](../../src/js/utils/bookmark-search.js#L17) · [前缀比较](../../src/js/utils/bookmark-search.js#L76)
