## 以前的检查为何漏掉这些问题

已有审计确实发现过天气缓存、旧书签字段和模态焦点问题。今天发现的缺口发生在不同的组合条件下。既有指纹测试覆盖安装和等待激活，已激活版本的导航快路径当时只检查缓存响应的成功状态。并发请求测试曾验证同一 URL 只下载一次，淘汰测试则验证单次扫描的 FIFO 结果。两者都没有把新写入安排在扫描取得快照之后。干净 CI 构建也没有本地发布测试所依赖的前一份 `dist`。参见[稳定性审查](./2026-11-06-v5.5.0-stability-audit.md)和[现有测试与架构](../ARCHITECTURE.md)。

Git 历史也表明问题来自不同阶段。淘汰合并代码在 `b08aa81`（2026-10-22）引入，旧导航快路径可追溯到 `7a97f0b`（2026-10-24），本地前版脚本保留在 `ea444e9`（2026-11-09）引入。审计时应区分已长期存在的边界缺口与近期新增链路的缺口。
