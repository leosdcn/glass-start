# 2026-10-28 中英文全站翻译与验证

开发分支：`codex/english-localization`。版本沿用 `package.json` 的 5.3.2，不涉及发布或推送。

## 实现范围

- 原生中英文消息字典，252 个键；支持参数与原生复数规则，无新增依赖。
- 静态文本、属性、动态提示、日期、天气、壁纸名称、快捷键、鸣谢和扩展元数据。
- 13 个内置分类及 127 个不同 URL 的书签展示内容翻译；用户改写与导入文字保持原文。
- 设置 → 数据管理 → 界面语言，可选跟随浏览器、简体中文、English；完成后刷新，取消不提交，保存失败保留草稿。
- 首屏同步确定语言，预渲染与应用共用上下文；字典不重复打进 app.js，不新增语言网络请求。
- 新天气缓存存代码与日期，渲染时翻译；旧数据、离线与地点名称更新保持兼容。
- Wikipedia 搜索与联想选择对应语言站点，网页响应头、页面 CSP 与扩展权限同步声明英文域名。

## 实际联网检查与边界

通过真实 Chrome 网页与已加载扩展请求英文 Wikipedia OpenSearch，均返回 HTTP 200 且数据结构正确。英文定位接口在 Node 和扩展中返回 HTTP 200；网页版同次检查返回 HTTP 429，属于外部服务限流，未反复重试。此轮不能确认网页版定位服务在未限流时的实际返回，但浏览器可以读取其响应，相关缓存与默认地点兜底由自动回归覆盖。

PWA 安装名称和爬虫抓取的静态默认元数据仍为中文；页面标题及可见界面随语言切换。外部地点专有名称在离线时允许保留缓存原文。RTL 语言不在本次支持范围内。

本次为开发分支实现，未变更版本号；没有进行发布。W3C 发布前校验留到实际发布阶段，按仓库发布规则执行。

## 本地预览修正

用户预览时发现计数显示 `bookmark.count`、切换后仍显示中文。实际 3000 端口由旧的 `node scripts/server.js --clear-cache` 进程占用，其内存中的旧构建逻辑重新覆盖了产物，输出页面不含语言初始化字典。此前只检查来源目录和 HTTP 200，未核实服务输出，导致预览交付失误。

已停止该旧进程，使用当前 `scripts/server.cjs` 重启，保留站点用户存储。直接通过 Chrome 访问实际 `http://localhost:3000/`，确认中文计数“已添加 8 项”、保存英文后计数“8 bookmarks added”，HTTP 输出也含语言字典。语言选择框复用现有 `settings-action` 玻璃样式，移除额外的顶部分割线。此轮 lint 31 项、语言专项 4 项（含类型检查与构建）通过；局部样式调整不重复全量回归。

随后根据用户对控件位置的反馈，将语言选择从“数据管理”内容区移到设置弹窗底栏左侧，右侧保留取消／完成。这样所有页签均能选择语言，数据区恢复原布局；刷新生效说明通过控件提示及无障碍描述保留。桌面与移动截图已检查，语言专项回归继续通过。
