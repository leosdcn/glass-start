# V5.5.0 稳定性逐文件审查

日期：2026-11-06。版本保持 `5.5.0`。环境：macOS、Node v26.13.0、npm 11.20.0、Chrome 156.0.8078.80。

## 范围与方法

以 Git 跟踪的 345 个文件为清单，按文件职责检查。人工阅读应用的 43 个 JavaScript 模块、类型声明、HTML、六份 CSS、Service Worker、十三份工程脚本及部署配置；核对状态流、异步任务、缓存读取、转义和扩展分支。测试按其入口和断言核对，32 份回归测试全部执行；98 份 JS/MJS/CJS 文件另经 Acorn 解析。资源文件按格式、引用、解码及页面表现检查，历史报告按链接和当前入口映射核对，不把旧报告的通过结论当作当前验证。

开始时 `test/weather-lab.html` 已有用户修改。本轮阅读其预览逻辑但未修改该文件；实验页不进入网页或扩展产物。没有添加运行时依赖，没有手改生成目录，没有提交、推送或发布。

## 已修复的问题

| 问题 | 触发与影响 | 修改与回归依据 |
| :--- | :--- | :--- |
| P2：重开弹窗时原生模态层顺序错误 | 打开设置和致谢，快速关闭后重开设置；退出中的致谢仍在原生 top layer，设置已经回到业务栈顶，但其输入框不能获得焦点。 | `core/overlay-stack.js` 对仍然 open 的窗口先关闭再调用 `showModal()`，使重开窗口重新置顶。`ui-modal-accessibility` 新场景在修复前确定失败、修复后通过。 |
| P2：天气首帧缓存可以形成 HTML 属性注入 | 缓存图标为含引号的 `.svg` 字符串时，首帧直接拼接 `src`，可形成额外事件属性；`__proto__` 还会误命中图标映射的原型属性，运行时可能抛出类型异常。 | 首帧只使用配置表自身的本地图标，其余使用 `textContent`；运行时映射也使用 `Object.hasOwn()`。`infra-security` 执行实际产物脚本，验证恶意字符串及原型键。这里只复现了异常本地缓存边界，未发现正常操作写入恶意缓存的链路。 |
| P2：搜索引擎恢复接纳原型属性 | `preferredEngine` 为 `"__proto__"`、`"toString"` 等合法 JSON 字符串时，旧的索引真假判断会当作合法引擎；首屏或运行时出现错误名称、空图标，部分值使首屏脚本异常。 | 首屏及 `setEngine()` 只接受对象自身键；初始化将类型检查后的值交给已有入口。`infra-theme-favicon` 验证首帧及真实控件事件的默认引擎回退。 |
| P2：多词模糊搜索忽略单字符条件 | `x y`、`x github` 等查询的单字符词被跳过，产生零距离或不受约束的匹配，返回不相关书签。 | 单字符不进行编辑距离容错，但必须命中词首。纯模型回归覆盖无关组合和仍应成功的拼写容错组合。 |
| P2：自定义壁纸首帧色调读取格式错误 | 运行时通过 `storageSet()` 保存 JSON 字符串，首屏却直接读取原值，导致 CSS 色调含额外双引号；应用执行后才修正。 | 首屏 JSON 解码并检查字符串类型。修正测试中手写原始值的夹具，使用真实持久化格式，在 defer 脚本执行前采样验证。 |
| P2：PWA 子目录部署共用根目录身份 | 根目录和子目录清单都固定 `id: "/"`，Chrome 将它们解析为同一个应用身份。 | 移除固定 id，使用 `start_url` 的默认身份。Chrome `Page.getAppManifest` 验证根目录仍为 `/`、子目录为 `/nested/`，且 scope 和启动入口相符。 |
| P3：历史测试报告存在十处失效链接 | 测试合并后，旧报告链接仍指向已删除文件。 | 链接改指当前合并入口，保留当时文件名、计数和结论，补充映射说明。 |

PWA 的处理依据是 [W3C Manifest 的 id 处理规则](https://www.w3.org/TR/appmanifest/#id-member)：缺省身份使用 `start_url`，显式相对 id 则基于入口的 origin 解析。因此不能简单把 `/` 改成 `./` 来解决子目录身份问题。已经按旧身份安装的子目录 PWA 不会由本次清单修改自动迁移为新身份；原快捷入口仍指向原地址，本轮未操作用户已安装的 PWA。

## 结论边界

本轮完成仓库文件检查及本地 Chrome 发布验证；不把测试通过等同于永久无缺陷。未对所有第三方书签网站逐站验收、未复核外部素材许可变更、未执行线上部署或检查本次提交的远程 CI。网络服务长期可用性和完整辅助技术符合性不由本轮结论保证。

按项目规则未安排 Safari/iOS 真机专项。最终全量回归 92/92 通过；没有必要但未完成的本地发布检查、遗留失败或环境阻塞。当前结果支持将 V5.5.0 作为待发布稳定版本候选，远程发布结果需以发布后的 CI 和部署为准。
