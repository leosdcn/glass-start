# Glass Start 多语言实施方案

状态：中英文已实施（2026-10-28），包含内置书签内容。本文保留设计范围和后续扩展约定；当前实现说明见 [架构文档](./ARCHITECTURE.md#多语言)，验证结果见本次交付记录。版本以 `package.json` 为准。

实施差异：消息与英文目录使用 JSON；语言控件位于弹窗底栏左侧，避免占用业务内容区；内置目录翻译已按用户“全站英语”要求一并完成。下文阶段划分保留原设计，本次已合并完成界面与目录翻译。导入来源仅增加草稿内临时标记，用户覆盖按字段持久化；新天气缓存移除派生文案，以新增加的每日天气代码兼容读取，不额外引入迁移状态机。

## 1. 目标与范围

采用原生 JavaScript 字典与少量翻译函数，网页和 Chrome 扩展共用。首期支持简体中文 `zh-CN`、英文 `en`，语言切换保存后刷新生效。新增普通从左向右语言时，主要工作应是翻译、语言登记和验收。

保留零第三方运行时依赖；不复制页面、业务模块、壁纸、图标或整份书签目录。不引入翻译服务、远程语言包、订阅系统、通用模板引擎或路由框架。

首期完整覆盖应用界面，包括动态提示、无障碍描述、日期、天气、壁纸名称、快捷键说明、鸣谢说明及扩展元数据。内置书签名称、简介与分类名称的翻译另列为第二阶段；发布说明必须明确这项内容边界。

## 2. 当前源码中需要处理的边界

| 位置 | 当前行为 | 方案要求 |
| :--- | :--- | :--- |
| `src/index.html` | 中文文本、属性、元数据，以及日期、天气和引擎预渲染脚本 | 静态标记与首屏翻译同源；预渲染直接使用选定语言 |
| `src/js/modules/`、`core/` | 弹窗、状态提示和 HTML 模板包含中文 | 使用完整句子的语义键 |
| `src/js/config/` | 壁纸、快捷键、鸣谢等包含显示文案 | 稳定业务标识不变，显示文本改为翻译键 |
| `utils/weather-model.js` | 生成中文天气描述和日期标签，缓存保存这些结果 | 新缓存存代码和日期，显示时翻译；兼容旧缓存 |
| `modules/weather.js` | 定位接口固定中文，部分地点处理采用中文行政区规则 | 按接口能力映射语言；中文规则仅用于中文数据 |
| `config/engines.js`、`modules/search.js` | Wikipedia 搜索与联想固定中文域名 | 单独制定站点语言映射，并同步权限与 CSP |
| `modules/bookmarks.js` | 通过名称、简介与目录比较判断用户自定义 | 第一阶段不改内容；第二阶段避免把显示译文保存为自定义 |
| `scripts/build-extension.cjs` | 通过匹配三句中文替换缓存说明 | 改为网页／扩展语义键，消除对中文原文的依赖 |
| `public/manifest.json` | PWA 名称、简介与语言固定中文 | 首期保留安装元数据边界，页面语言正常切换 |

## 3. 语言选择与持久化

### 3.1 选择规则

设置增加原生下拉框，放在现有设置面板的通用偏好区，不新增独立弹窗：

- 跟随浏览器 / Follow browser
- 简体中文
- English

语言名称使用该语言自身的名称，避免切换后找不到入口。字段旁说明“点击完成后刷新生效”，采用当前页面语言。

新增 `CONFIG.KEYS.LANGUAGE`，建议键名 `glass_language`，值为 `auto` 或已支持的语言代码。缺失、损坏或已移除的语言值按 `auto` 处理。LocalStorage 读取失败时使用浏览器偏好，不影响页面启动。

解析顺序：有效手选语言 → 按 `navigator.languages` 顺序匹配 → `navigator.language` 兜底 → 英文。默认设置为 `auto`；无匹配语言时使用英文。浏览器偏好是语言列表，不能用 IP、所在国家或时区替代。

匹配使用显式语言注册与别名，不把任意语言简单截成前两个字母：

| 输入示例 | 首期结果 |
| :--- | :--- |
| `en-US`、`en-GB` | `en` |
| `zh`、`zh-CN`、`zh-SG`、`zh-Hans` 及其地区形式 | `zh-CN` |
| `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` 及其地区形式 | 首期明确回退 `zh-CN`；以后新增繁体时优先匹配繁体 |
| `fr-FR, en-US` | `en` |
| 全部不支持 | `en` |

未来注册 `pt-BR`、`pt-PT` 等变体时，明确默认变体和回退顺序，不依赖字典遍历顺序。无效语言标识不允许导致 `Intl` 抛错中断初始化。

### 3.2 保存语义

增加 `modalState.draftLanguage` 并同步类型；打开设置时读取偏好，选择仅修改草稿，取消不保存。

沿用 `saveEditModal()` 的草稿与异步请求有效性检查：等待壁纸保存完成，保存书签与暗度，再提交语言。语言写入失败时保留弹窗、草稿和原页面语言，并说明其他已经保存的项目仍然生效；不额外构建跨存储事务。

全部保存成功后，语言偏好变化则关闭弹窗并刷新一次。偏好未变化不刷新；即使 `auto` 与手选语言当前解析结果相同，偏好发生变化也允许刷新，以保持流程简单。刷新后依照新的有效语言初始化所有模块。

“恢复全部设置”包含语言偏好，成功后回到 `auto` 并刷新；部分重置失败时遵循现有失败提示，不盲目刷新。书签导入／导出保持书签数据范围，不夹带语言设置。

现有用户没有语言键，升级后按 `auto` 解析；英文浏览器用户可能首次自动进入英文，这是明确的产品行为，不靠猜测旧用户身份写入中文偏好。

网页与扩展保持各自来源的存储；其他标签页及浏览器语言改变均在下次加载生效，不新增实时广播或自动刷新。

## 4. 代码组织与翻译接口

建议新增：

```text
src/js/config/locales/
  index.js       # 共用消息注册
  zh-CN.json     # 中文消息
  en.json        # 英文消息
src/js/core/i18n.js
                 # 语言解析、翻译、参数替换、静态节点翻译
```

语言字典使用扁平语义键和纯数据，不存 HTML、URL 或可执行函数。例如：

```json
{
    "settings.title": "设置与偏好",
    "settings.save": "完成",
    "language.reload": "点击完成后刷新生效",
    "bookmark.addLabel": "添加快捷书签：{name}",
    "bookmark.importConfirm": "将 {count} 个书签导入草稿，点击“完成”后生效。",
    "cache.web.description": "若离线资源异常或更新未及时应用，可手动刷新离线缓存。",
    "cache.extension.description": "可清理临时缓存并刷新页面，不影响已保存的书签、壁纸和设置。"
}
```

最小接口为 `getLocale()`、`resolveLocale(preference, browserLanguages)`、`t(key, params)`、`applyTranslations(root)`。初始化接收构建注入的语言注册数据，解析函数保留纯函数形式，便于直接单元测试。语言设置事件留在 `modules/settings-events.js`，应用启动顺序由顶层装配。

每次加载确定一次有效语言；不提供运行时 `setLocale()` 或语言变更事件总线。字典与语言配置只维护一份源码。

### 4.1 消息规则

- 一条消息表达完整句子，不拼接“已添加”“个”“成功”等语序片段。
- 参数替换为一次替换，不递归解释参数内容，不使用 `eval`、模板编译或正则执行表达式。
- 运行时缺键回退英文，再显示键名以便排查；正式支持的语言必须通过键完整性校验，回退不是允许漏译的理由。
- 数量消息允许 `{ one, other }` 等复数分支，通过 `Intl.PluralRules` 选择；按该语言实际需要扩展 `zero/two/few/many`，必须有 `other`。无需实现完整 ICU 语法。
- 每个分支使用相同的参数约定；数量仍为数值参与规则选择，显示时可用 `Intl.NumberFormat`。
- 字典不存 HTML；动态模板先 `t()`，再 `escapeHtml()`。属性中的动态文字同样转义，URL 仍用 `safeUrl()`。`textContent` 直接接收翻译结果。
- 许可标识、产品名称、快捷键符号、日志与内部错误码不强制翻译；用户可见的解释需要翻译。

### 4.2 静态 HTML

文本与属性分别标记，例如：

```html
<span data-i18n="settings.save">完成</span>
<input data-i18n-placeholder="search.placeholder"
       data-i18n-aria-label="search.inputLabel">
```

仅支持实际需要的白名单属性，如 `placeholder`、`title`、`aria-label`、`alt`。不允许翻译修改 `href`、`src`、事件属性或任意 HTML。`data-i18n` 放在专门的文本叶节点，不用 `textContent` 覆盖含图标或交互控件的父节点。

模板默认中文回退文本允许保留，但由校验保证与中文消息一致，新增文案优先在字典修改。动态生成的节点由模块调用 `t()`，不对每次渲染后的整个文档重复扫描。

新增通过 `dom.xxx` 访问的语言控件要登记 `cacheDOM()` 和 `DOMCache`；批量翻译使用 `data-*` 查询，不为每条文本新增 DOM 缓存字段。

## 5. 首屏、构建和离线

### 5.1 数据与执行顺序

利用 `scripts/build.cjs` 现有 esbuild 注入能力，生成语言初始化脚本。首期两种语言随本地 HTML 初始化资源打包，不请求远程字典，不动态导入语言文件。

执行顺序：

1. head 中同步读取偏好、解析语言，初始化共享翻译上下文，设置 `html.lang` 与 `html.dir`。
2. 现有日期、天气和引擎预渲染读取同一上下文，直接生成当前语言。
3. body 末尾、应用初始化之前，同步翻译静态文本、属性和页面标题。
4. 应用模块使用已确定的语言渲染动态内容。

语言字典仅放进一次首屏初始化产物；应用包不再次导入整份字典。head 与应用共享一个命名空间下的语言上下文，模块通过 `core/i18n.js` 访问。构建入口可引用注册数据及初始化函数，应用入口只引用运行时函数；实现后检查 esbuild 产物，确认没有重复打包字典。少量共用函数在不同构建入口中的重复压缩代码可接受，不为消除几十行逻辑建立加载框架。

### 5.2 防止中文闪现

仅在 head 设置 `lang` 不会自动翻译后续 HTML，body 末尾执行也不能单独保证浏览器从未提前绘制。因此对需要静态翻译的可见内容使用局部预翻译遮蔽：

- head 初始化成功后，且有效语言不是模板默认中文时，设置短暂的 pending 标记。
- 只暂时隐藏含静态文案的前景区域，保留壁纸和底色，不添加全屏加载器。
- body 末尾的本地同步翻译在 `finally` 中解除标记，不等待天气、壁纸、网络或应用主包。
- 无脚本时不设置 pending，保留默认内容；翻译初始化失败不得留下永久隐藏。设置最小的超时解除兜底，以覆盖扩展末尾外置脚本加载失败，正常路径立即清除该兜底。

这是为首屏一致性引入的局部机制；应通过慢速加载截图验证，测量实际首屏影响，不能只检查最终 DOM 就宣称没有闪现。

### 5.3 构建安全与缓存

翻译内容注入脚本时沿用 `</script>` 边界保护，并正确序列化文本。构建插槽必须唯一，缺失或重复时阻断构建。新增脚本顺序在网页版和扩展中一致。

网页版初始化资源内嵌在现有 HTML，沿用 HTML／app／SW 构建指纹及核心缓存，不新增语言缓存池，也不因选择不同语言生成多份 URL 或缓存键。离线切换语言依赖已缓存应用资源，语言切换本身不需要网络。

扩展继续把新增内联初始化脚本外置为本地 `bootstrap-*.js`，不放开 CSP、不加载远程代码、不注册 SW。网页和扩展差异通过已有构建标记选择 `cache.web.*` 或 `cache.extension.*`，删除构建脚本对中文整句的替换。

## 6. 日期、天气和搜索

### 6.1 日期与数值

首屏日期与运行时日期共用格式策略，使用 `Intl.DateTimeFormat(locale, options)`。天气预报工作日也通过 `Intl`，今天／明天使用字典。当地时钟继续使用设备时区、24 小时格式，保持现有产品行为。

天气预报日期按地点本地日历日期处理，不把 `YYYY-MM-DD` 当 UTC 时间转换后偏移一天；日出日落沿用接口地点时间，先进行现有时间校验。天气输入数值仍先经 `weatherNum()` 清洗再格式化。首期继续摄氏度与现有风速单位，语言选择不自动改成华氏度或更改时区。

### 6.2 天气缓存

新缓存以语言无关数据为主：当前天气代码、每日纠偏后的天气代码、日期、数值、图标所需状态与时间戳。中文 `weatherText`、每日 `text`、`label` 不再作为显示依据；地点文字单独带来源语言标记。

兼容旧缓存：当前天气可用现有 `weatherCode` 重建译文；每日旧记录没有代码时，保留温度与日期，状态描述使用本地化的未知状态，不反向解析中文猜代码。后台按正常刷新路径补齐新结构，离线仍能使用已有有效数值。缓存增加一个必要的结构版本字段；不改书签或壁纸存储格式。

天气模型输出代码和数据，不读取 DOM 或全局语言。描述由渲染端翻译，首屏天气预渲染也复用对应代码映射。涉及天气模型类型、缓存读取器与现有回归断言时一起调整。

### 6.3 地点名称与接口语言

语言注册表为各服务显式记录映射；应用语言码不直接假设等于接口参数。首期中文沿用当前定位策略；英文优先使用现有支持英文的定位服务，并避免把中文行政区去后缀规则用于英文文本。

坐标可跨语言复用，地点显示名称带语言标记。切换语言后优先保留可用坐标和气象数据；名称不匹配时异步更新，不为翻译城市名清空天气或阻塞首屏。离线允许保留原地点名称，这是外部专有名词，不伪造机器音译。

默认上海坐标保持原值，名称由字典显示为“上海”或“Shanghai”。外部服务不支持的语言明确回退英文，网络响应文字始终按外部输入处理。

### 6.4 搜索

搜索引擎选择与用户查询保持原样。Wikipedia 首期按语言映射到中文站或英文站，搜索 URL、联想接口、首屏引擎元数据使用同一映射；扩展精确补充 `en.wikipedia.org` 权限与 `connect-src`，不使用泛域名权限。

Bing／Google 的语言参数只使用实施时核实的现有接口能力；不承诺联想结果一定与界面同语言。语言加入相关请求的内存缓存键；现有 JSON 与 JSONP 分支约束继续生效。语言字典不控制网络 URL。

## 7. 书签内容的第二阶段

首期分类、书签名称和简介保留现有内容，按钮、计数、编辑器提示与搜索分组标题全部本地化。用户创建、编辑或导入的文字始终保留原文。

后续翻译内置内容时采用展示映射，不能复制整份目录：

- URL、图标和顺序仍在 `bookmarks.json`；书签译文以现有规范化完整 URL 定位。分类使用现有稳定 ID（若没有则新增最小 ID），不以数组位置或中文名称作为长期身份。
- 翻译只在展示模型中生效，原始目录和用户覆盖元数据保留；名称、简介分别判断有无用户覆盖，显式空简介不得被译文填回。
- 编辑草稿仍是唯一保存与导出来源。编辑器若展示内置译文，保存时必须辨别“继承内置值”和“用户改写”，不能仅比较中文目录与英文草稿。
- 尽量由原始目录、现有覆盖字段与本次草稿比较判断来源；确有歧义才增加最小字段来源标记，不创建第二套持久化书签体系。
- 必须覆盖：只排序再保存、只改图标、只改名称、清空简介、导入自定义名称、跨语言再次打开编辑器。尤其验证不修改文字时不会把内置译文固化成用户覆盖。
- 书签备份继续从草稿导出当前可见文字，保证自包含且导出所见即所得。重新导入按用户内容保留，不保证导入后的内置译文继续随语言变化；若将来需要保留继承关系，另行设计版本化备份格式。
- 搜索需要匹配显示译文及用户文字，原始名称可作为别名；仍按 URL 去重，不改变持久化键语义。
- 中文原始简介沿用现有 lint 限制；译文采用语言相关的长度提示与实际布局验收，不套用“纯中文 9 字”作为所有语言的限制。

该阶段触及书签派生和保存语义，应单独实施与回归，不与首期简单抽取文案混在一起。

## 8. 扩展、PWA 与网页元数据

扩展清单改用 `__MSG_extensionName__`、`__MSG_extensionDescription__` 和 `default_locale`。构建从同一语言字典生成 `_locales/zh_CN/messages.json`、`_locales/en/messages.json`，应用语言码和 Chrome 目录码分开登记，禁止手工维护第二份译文。扩展默认元数据采用英文，品牌名 Glass Start 保持不变。

扩展管理页名称跟随 Chrome 的扩展语言机制；页面内手选语言不能修改浏览器管理页的语言。二者不同是预期行为。

网页运行时更新 `document.title`、描述和相关可访问文本。静态 HTML 的社交卡片、结构化数据及 PWA 安装元数据首期保持中文默认，不声称运行时切换能改变爬虫抓取结果或已有安装名称。PWA 在离线重开和页面内切换时仍按用户设置显示界面。

若以后有多语言 SEO 或安装名称需求，再增加静态语言页面和对应 manifest；首期不增加路径路由、`hreflang` 或安装身份变化。

## 9. 新语言扩展流程

1. 从完整基准字典复制键，翻译整句、参数与实际需要的复数分支。
2. 注册语言自身名称、BCP 47 代码、别名、`dir`、Chrome 目录码及各接口语言映射。
3. 运行键、参数、复数分支和静态引用校验。
4. 验收日期、数字、设置、错误提示、窄屏与离线；构建自动生成扩展元数据。
5. 如需翻译书签内容，独立补展示映射，不改用户数据。

新增日语、韩语、法语、德语、西班牙语等不应要求修改核心业务流程。字体优先现有系统字体，不为新增语言下载字体文件。翻译质量仍需要相应语言的人工审阅。

先支持 LTR 语言。注册表预留 `dir`；阿拉伯语、希伯来语不能仅加字典就宣布支持，届时需审查左右定位、箭头语义、拖拽、横向滚动、混合方向 URL 与数字，并按需采用逻辑 CSS 属性及 `bdi`。首期不提前全面改写方向相关布局。

## 10. 体量与性能预算

新增成本主要是文字字典、翻译函数和 HTML 标记；图片、字体和运行时依赖的新增预算为零。中英文界面预计为几十至低数百 KiB 的源码／未压缩产物增量，实际由文案数量与实现决定，不把此前“几十 KB”的估计作为保证。

实施前后在相同依赖和构建模式下记录：

| 指标 | 测量范围 |
| :--- | :--- |
| 网页代码体积 | `index.html` + `app.js`，分别记录原始与 gzip 字节数 |
| 网页完整产物 | `dist/` 总字节数，确认壁纸图标没有复制 |
| 扩展体积 | `extension/` 总字节数与压缩包字节数，含 bootstrap 与 `_locales` |
| 网络成本 | 首次访问请求数；语言初始化额外网络请求为零 |
| 首屏表现 | Chrome 同条件重复采样，观察首屏、语言遮蔽时长与慢速加载截图 |

中英文第一阶段以代码原始增量不超过 200 KiB 为目标，超过时定位重复字典和无关资源，不能以 1 MB 作为放宽目标。这是设计预算，只有构建实测才是交付数字。网页和扩展分别比较，不能把两个独立发布包相加当作单端增量。

未来每加一种语言主要增加其文本数据；语言变多且实测出现明显成本时，再评估本地分包及离线预缓存，不预先建设语言加载框架。

## 11. 校验、测试与验收

### 11.1 静态校验

扩展现有 lint 入口，检查已注册语言的键集合、消息类型、占位符集合、必需的复数 `other` 分支、语言别名冲突、HTML 翻译属性及静态翻译引用。动态键仅允许可枚举的配置映射，如天气代码映射；配置所引用键必须可校验。

不使用“源码出现中文即失败”的粗暴规则，避免误报注释、日志和用户数据。残余用户界面文案通过分模块清单审查与浏览器验收确认。

### 11.2 直接回归

- 纯单元：语言列表优先级、地区／文字变体、异常输入、回退、参数不递归替换、复数分支。
- 浏览器：`auto`／手选／取消／保存失败／保存成功仅刷新一次／重置；`lang`、标题和 ARIA 同步；用户书签文字不变。
- 首屏：首次英文访问、已保存英文、旧中文天气缓存、慢速加载、主包或末尾翻译脚本加载失败后不会永久隐藏、离线切换。
- 天气：新旧缓存、代码翻译、日期不偏移、地点语言不匹配、定位失败与离线数据保留。
- 搜索：中文／英文 Wikipedia 的搜索和联想，网页与扩展分支、精确域名权限。
- 布局：Chrome 桌面与 CDP 移动／触摸，英文长文案、200% 缩放、键盘操作、弹窗焦点和控件字号。
- 扩展：本地脚本与 CSP、清单语言目录、管理页名称、页内语言选择、无网页 SW。

优先扩展已有设置、天气、搜索、无障碍及扩展用例；确有未覆盖行为时增加少量 i18n 用例，纯单元放在 `test/` 顶层，辅助放在 `test/support/`。

### 11.3 执行范围

实施子阶段先运行 `npm run lint` 及直接相关测试。浏览器测试经 `npm test -- <具体文件片段>` 执行，由运行器处理类型检查与构建；纯单元可直接 `node --test`，不重复构建。

第一阶段整体涉及构建入口、首屏和多个模块，集成完成后执行 `npm run lint` 与 `npm test`，包含扩展回归；同一轮通过后不重复全量。发布前再按仓库发布规则完成 `npm run test:w3c`。远程接口域名变更需要网页版与扩展的实际联网走查。

新增单个语言时以字典校验、该语言界面预览和扩展构建回归为主；没有新增逻辑不重复全量测试。书签内容第二阶段根据实际派生／持久化影响选择对应数据测试，范围无法可靠界定时执行全量。

## 12. 实施顺序与完成定义

| 顺序 | 交付内容 | 完成条件 |
| :--- | :--- | :--- |
| 1 | 基线记录、字典、语言解析与校验 | 无新增运行时依赖，键及参数校验通过 |
| 2 | head 初始化、静态标记、动态模块文案 | 首屏与主应用同语言，网页离线可用 |
| 3 | 语言设置草稿、保存、失败和重置流程 | 无草稿丢失，保存后正确刷新，取消不提交 |
| 4 | 日期、天气模型与缓存兼容、搜索映射 | 旧缓存及离线可用，新域名权限精确匹配 |
| 5 | 扩展元数据、构建替换清理、布局与集成验收 | 网页和扩展通过相关及整体检查，给出体积实测 |
| 6 | 后续内置书签内容翻译 | 原文／译文／用户覆盖边界及导入导出回归通过 |

第一阶段交付时更新 README 的语言设置说明和 ARCHITECTURE 的配置、初始化及缓存说明，并列出检查结果、实际体积变化与未完成验收。实现不主动变更版本号，不执行 Git push。

本方案中的预算与验证清单属于设计要求；实际检查结果和测量数据以交付记录为准。
