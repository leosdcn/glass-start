# 切屏帧间隔评测

```sh
npm run benchmark
npm run benchmark -- --rounds 10 --native --json /tmp/glass-transition.json
npm run benchmark -- --compare http://127.0.0.1:5130/
```

命令先构建，再测本地生产产物，不注入测试接口。默认重复 5 轮、CPU 4 倍降速、1920×1080、设备像素比 2。`--compare` 是可选对照地址，仅在明确提供时访问；应指向另一份 Glass Start。两个地址顺序运行，各使用全新的临时 Chrome 配置。对照版本必须自行构建、启动，脚本不会切换 Git 分支。

## 测量口径

- 首次进入单独测量，不先切屏预热。使用新配置、绕过 Service Worker；等待页面及字体就绪，并采样 30 个空闲帧校准基准帧间隔。它代表加载完成后的首次切屏，不包含页面启动耗时，也不保证网络资源全部冷加载。
- 首次返回单独列出；随后记录多轮进入、返回的原始数据，不把首次样本混入重复样本。
- 从方向键触发开始，到目标屏幕类生效、切屏状态解除、屏幕及内容区域的 CSS 过渡结束、进入时内容不透明，并连续 3 帧稳定后结束。因而能覆盖解除切屏状态后才开始的淡入，而非只测推移动画。超时或没有到达目标状态会失败退出。
- 输出每组的时长中位数、时长 P95、帧间隔 P95、最大帧间隔及超过基准 1.5 倍的间隔数。估算漏帧根据每个间隔相对基准的倍数计算，不是浏览器实际提交帧统计。
- JSON 保留每轮完整帧间隔、时长、参数、时间、浏览器版本及页面可用的构建指纹，方便复核。各组采样长度不同，长间隔数量不宜脱离时长直接比较。

## 使用限制

这是无头 Chrome 的主线程 `requestAnimationFrame` 间隔评测，沿用测试浏览器的 `--disable-gpu` 配置，不能测量真实显示器呈现帧率、GPU 合成成本，也不能替代 Safari/iOS、毛玻璃与触控板实测。逐帧读取动画状态本身也有开销。

默认本地是指评测目标；页面自身的天气等网络请求仍按应用行为发生。

总时长包括末尾 3 帧稳定确认，不能直接当作 CSS 动画声明时长。不同设备、后台负载、浏览器版本和运行次序都会影响结果；比较时保持条件一致，必要时交换运行顺序复测。少量样本的 P95 接近最大值，应结合原始数据判断。脚本不设性能通过阈值，也不会自动认定某个版本更快。
