# 切屏帧间隔评测

```sh
npm run benchmark
npm run benchmark -- --rounds 10 --native --json /tmp/glass-transition.json
npm run benchmark -- --throttle 4
npm run benchmark -- --compare http://127.0.0.1:5130/
```

命令先构建，再测本地生产产物，不注入测试接口。默认重复 5 轮、CPU 原速、1920×1080、设备像素比 2。`--throttle 4` 显式启用 4 倍 CPU 降速压力测试，`--native` 显式指定原速。`--compare` 是可选对照地址，仅在明确提供时访问；应指向另一份 Glass Start。两个地址顺序运行，各使用全新的临时 Chrome 配置。`--rounds` 接受 1–50 的整数，表示首次进入和首次返回之外的重复轮数；`--throttle` 接受 1–20，和 `--native` 同时指定时以后出现的参数为准。对照版本必须自行构建、启动，脚本不会切换 Git 分支。

## 测量口径

- 首次进入单独测量，不先切屏预热。使用新配置、绕过 Service Worker；等待页面及字体就绪，并采样 30 个空闲帧校准基准帧间隔。它代表加载完成后的首次切屏，不包含页面启动耗时，也不保证网络资源全部冷加载。
- 首次返回单独列出；随后记录多轮进入、返回的原始数据，不把首次样本混入重复样本。
- 从方向键触发开始，到目标屏幕类生效、切屏状态解除、两个屏幕节点及导航内容节点自身的 CSS 过渡结束、进入时内容不透明，并连续 3 帧稳定后结束。因而能覆盖解除切屏状态后才开始的淡入，而非只测推移动画。超时或没有到达目标状态会失败退出。采样期间不遍历书签动画，只在解除切屏状态后检查上述三个节点；“稳定”仅指这些状态连续满足，不表示全部图片解码、子节点动画或最终绘制均已完成。
- 输出每组的时长中位数、时长 P95、帧间隔 P95、最大帧间隔及超过基准 1.5 倍的间隔数。时长统计以每轮总时长为样本；帧间隔统计将同组各轮的间隔合并计算，P95 使用升序数组的第 `ceil(N × 0.95)` 项，不做插值。估算漏帧为各间隔的 `max(0, round(间隔 / 基准间隔) - 1)` 之和，不是浏览器实际提交帧统计。
- JSON 保留每轮完整帧间隔、时长、参数、时间、浏览器版本及页面可用的构建指纹，方便复核。各组采样长度不同，长间隔数量不宜脱离时长直接比较。

## 使用限制

这是无头 Chrome 的主线程 `requestAnimationFrame` 间隔评测。评测入口允许 GPU 加速（普通回归测试仍默认使用 `--disable-gpu`），但未验证浏览器最终是否使用硬件加速。不能测量真实显示器呈现帧率、GPU 合成成本，也不能替代 Safari/iOS、毛玻璃与触控板实测。采样和收尾检测本身也有开销。早期禁用 GPU、逐帧遍历书签动画的评测结果不应与当前口径直接比较。

默认本地是指评测目标；页面自身的天气等网络请求仍按应用行为发生。

总时长包括末尾 3 帧稳定确认，不能直接当作 CSS 动画声明时长。不同设备、后台负载、浏览器版本和运行次序都会影响结果；比较时保持条件一致，必要时交换运行顺序复测。少量样本的 P95 接近最大值，应结合原始数据判断。脚本不设性能通过阈值，也不会自动认定某个版本更快。
